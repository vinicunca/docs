**UnoCSS Variants** (`unocss-variants`) is a first-class variant API for [UnoCSS](https://unocss.dev/). You define a component recipe once — base styles, variants, defaults, slots, and compound rules — and call it anywhere with typed props.

It is a port of [Tailwind Variants](https://www.tailwind-variants.org/). The important difference: **classes are never merged**. Conflicting utilities stay in the class string; you resolve them with UnoCSS [layers](/unocss-variants/concepts/layers) and the CSS cascade.

::note
`uv(options)` takes **one** argument. There is no config object, no `twMerge`, no `/lite` build, and no responsive-variant map. Put breakpoint prefixes such as `md:` in the class strings yourself.
::

## Key features

### Variants

Define axes like `color`, `size`, or boolean flags such as `disabled`. Combine them independently.

::code-preview{class="[&>div]:*:my-0"}

:::uv-button
---
as: button
size: sm
color: secondary
uv:
  base: font-medium bg-blue-500 text-white rounded-full active:opacity-80
  variants:
    color:
      primary: bg-blue-500 text-white
      secondary: bg-purple-500 text-white
    size:
      sm: text-sm
      md: text-base
      lg: px-4 py-3 text-lg
  defaultVariants:
    size: md
    color: primary
  compoundVariants:
    - size:
        - sm
        - md
      class: px-3 py-1
---
Click me
:::

::

```vue
<script setup>
import { uv } from 'unocss-variants';

const button = uv({
  base: 'font-medium bg-blue-500 text-white rounded-full active:opacity-80',
  variants: {
    color: {
      primary: 'bg-blue-500 text-white',
      secondary: 'bg-purple-500 text-white'
    },
    size: {
      sm: 'text-sm',
      md: 'text-base',
      lg: 'px-4 py-3 text-lg'
    }
  },
  compoundVariants: [
    {
      size: ['sm', 'md'],
      class: 'px-3 py-1'
    }
  ],
  defaultVariants: {
    size: 'md',
    color: 'primary'
  }
});
</script>

<template>
  <button :class="button({ size: 'sm', color: 'secondary' })">
    Click me
  </button>
</template>
```

```ts
button({ size: 'sm', color: 'secondary' });
// font-medium bg-blue-500 text-white rounded-full active:opacity-80 bg-purple-500 text-white text-sm px-3 py-1
```

Every class is kept, including both `bg-blue-500` from `base` and `bg-purple-500` from the variant. See [Layers](/unocss-variants/concepts/layers) for how to make the variant win.

See [Variants](/unocss-variants/concepts/variants) for boolean variants, compound variants, and defaults.

### Overrides

Pass `class` or `className` when you call the recipe. The extra classes are **appended** — they do not replace conflicting utilities.

```ts
button({
  color: 'secondary',
  class: 'bg-pink-500 hover:bg-pink-500'
});
// font-semibold text-white py-1 px-3 rounded-full active:opacity-80 bg-purple-500 hover:bg-purple-700 bg-pink-500 hover:bg-pink-500
```

See [Overriding styles](/unocss-variants/concepts/overriding-styles).

## What is not included

- **No class merging** — unlike default Tailwind Variants, `uv` never drops conflicting utilities.
- **No second `config` argument** — and no `createTV` / `twMerge` / `cnMerge`.
- **No `/lite` entry** — there is a single build.
- **No `responsiveVariants` map** — write `sm:` / `md:` in the class strings.
- **No breakpoint autocompletion** — TypeScript completes variant keys and slot names, not media queries.

Coming from Tailwind Variants? Read the [migration guide](/unocss-variants/guides/migration).
