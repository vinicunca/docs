# Issues found while reviewing the windows-dev skill

Found on 2026-10-10 while writing `docs/skills/windows-dev` from `docs/content/windows-dev`. Every item was confirmed unless marked unverified.

## Docs (`content/windows-dev`)

- [ ] **VPN DNS fix does nothing.** The page says `/etc/wsl.conf` "can pin Windows DNS" with `generateResolvConf = true`, but `true` is already WSL's default, so adding it changes nothing and a reader with broken DNS stays stuck. Evidence: `content/windows-dev/2.extras/3.troubleshooting.md:60`, `content/windows-dev/2.extras/3.troubleshooting.md:62-65`. Fix: replace it with a setting that actually changes DNS behavior (for example `dnsTunneling=true` under `[wsl2]` in `.wslconfig`, verify first), or remove the snippet and link Microsoft's VPN guidance.
- [ ] **VS Code Server reset deletes WSL extensions without warning.** `rm -rf ~/.vscode-server` also removes every extension installed in the WSL window (ESLint, Vue, UnoCSS), and the page doesn't say so. Evidence: `content/windows-dev/2.extras/3.troubleshooting.md:42`. Fix: add a note that WSL-side extensions must be reinstalled afterward (the `code --install-extension` list in the VS Code page).
- [ ] **Node LTS claim is about to go stale.** "As of October 2026, Active LTS is the 24.x line" will be wrong once Node 26 enters Active LTS, expected later in October 2026 (exact date unverified). The `fnm install 22` / `fnm use 24` examples age with it. Evidence: `content/windows-dev/1.guide/7.nodejs.md:40`. Fix: drop the version claim and rely on `fnm install --lts`, or link the Node release schedule.
- [ ] **pnpm version mismatch (unverified).** The warning names pnpm 12 as the release that refuses root (`ERR_PNPM_SUDO_NOT_SUPPORTED`), while the pin example uses `PNPM_VERSION=10`. I couldn't confirm that pnpm 12 exists or that the error code belongs to it. Evidence: `content/windows-dev/1.guide/8.pnpm.md:30`, `content/windows-dev/1.guide/8.pnpm.md:34`. Fix: check the pnpm changelog and correct the version, or reword without a version number.
- [ ] **localhost troubleshooting step is vague.** "not a stale Windows-only NIC" gives the reader nothing to check or change. Evidence: `content/windows-dev/2.extras/3.troubleshooting.md:30`. Fix: say what to check, for example the host the dev server prints on startup and its `--host` flag.
- [ ] **NAT port-forwarding claims disagree.** The WSL page says NAT "still forwards `localhost` ports" (so dev servers work either way); troubleshooting says it forwards only "most" ports. Evidence: `content/windows-dev/1.guide/4.wsl.md:105`, `content/windows-dev/2.extras/3.troubleshooting.md:28`. Fix: use the same wording in both places.
- [ ] **Clock fix omits the install command.** The page says to "install `systemd-timesyncd`" but gives no command, unlike every other step. Evidence: `content/windows-dev/2.extras/3.troubleshooting.md:56`. Fix: add `sudo apt install -y systemd-timesyncd`.
- [ ] **Extension install location contradicts itself.** The intro says to install every listed extension "in WSL", but the first table row says to install the WSL extension on Windows. Evidence: `content/windows-dev/1.guide/9.vscode.md:85`, `content/windows-dev/1.guide/9.vscode.md:89`. Fix: take the WSL extension out of the table, or limit the intro sentence to the other extensions.
- [ ] **Chocolatey one-liner is missing Bruno.** The WinGet list installs Bruno, but the Chocolatey equivalent doesn't. Evidence: `content/windows-dev/1.guide/3.package-managers.md:152`, `content/windows-dev/1.guide/3.package-managers.md:161`. Fix: add the Chocolatey package for Bruno (check its name), or note that it's WinGet-only.
